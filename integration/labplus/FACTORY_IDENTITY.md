# Spark 离线出厂证书、设备签名与黑名单

正常设备无需逐台向服务器登记。服务器只信任工厂 CA 公钥，保存需要停用的设备黑名单。网页与 ESP 后端共用这些规则。

## 后续旧设备兼容原则

统一的是出厂证书、挑战签名和服务器验签协议，每台设备仍使用独立密钥，不共用设备私钥。身份与可升级固件分离；旧设备适配在确认板型和安全能力后增加，不自动降级认证。

经典 ESP32 虽有 eFuse，但没有 P4 的专用 ECDSA 私钥签名通路。软件可读的 eFuse 可以在擦除 Flash 后保存私钥，却不能阻止用户自编固件读取并复制私钥。只读保护又会让软件无法取出私钥签名。因此在允许任意自编固件的前提下，不能只靠经典 ESP32 内部 eFuse 同时保证身份持久化和私钥不可复制；可增加外部安全芯片，在其内部生成、保存私钥并签名。

带 RSA DS 的其它型号需要单独适配算法与证书格式；其 eFuse 保护密钥并不等于所有签名参数都在 eFuse 内，部分加密参数仍需 Flash 持久分区或恢复包。当前实现只接受 P-256，尚未实现或验证旧设备驱动。不得把旧设备软件存储密钥宣称为同等级硬件保护。

## 两层证明

1. 工厂专用固件在设备内生成 P-256 密钥。私钥写入 KEY0，设置 ECDSA 专用用途、读保护、写保护和用途写保护；清除 RAM 临时密钥。正式固件仅调用硬件签名，不导出私钥。
2. 离线工厂电脑用厂商 CA 私钥签署 UTF-8 `SPARK-CERT-V1\nspark.mpython.cn\n<12位设备编号>\n<SPKI DER公钥的base64>`。证书采用固定 64 字节 P1363（r||s）签名，写入 KEY1/KEY2，并设置写保护和用途写保护。这两块是公开数据，不设置读保护。公钥由硬件重建。
3. 设备向服务器提供编号、公钥和证书。服务器用预配置的厂商公钥验签，并检查黑名单，不相信客户端声称的“合法”“串口连接”“eFuse 已保护”等标志。
4. 服务器发出含随机数、站点、设备编号、请求摘要、到期时间的一次性挑战，30 秒内有效。设备用自己的私钥签署挑战，服务器再次验签。签名绑定原请求；改变内容、重放、过期、冒用编号、公钥替换、自签证书均被拒绝。

复制证书/固件不能得到设备私钥。公开固件和刷机工具不包含厂商私钥、管理员密码或千问 API Key。

## 刷机与持久化

身份与证书均位于 eFuse，独立于 Flash，普通升级或整片擦除 Flash 不会清除它们。用户刷回支持该协议的固件即可恢复同一身份；自编固件不实现协议时无法使用此服务。

占用 KEY0/KEY1/KEY2 共三个 eFuse 密钥块。首次烧写前必须确认这些块没有用于其它安全功能。工厂固件遇到已占用块不会覆盖。KEY0 部分写入、证书块部分写入、断电等异常必须隔离核查，不能强行重新签发/重新烧写。

普通升级：
`python tools/update_device.py --port 串口 --firmware edge_agent.bin --sha256 发布包SHA256`

工具只更新设备报告的当前应用槽，并核对现有分区表、镜像大小及 SHA256；备份旧应用，升级后比较公钥。不会写 NVS、OTA 元数据、分区表、storage 或 eFuse。旧固件没有协议时拒绝猜测地址。

SD 资源升级合并官方 `labplus/` 文件，保留 `programs/`、用户文件、Wi-Fi、开机选择、scheduler/router 配置。首次工厂镜像和产品镜像分区不同，只能使用各自构建包中的 `flasher_args.json`；不能把出厂镜像当普通升级包。

## 离线出厂

在完成下面安全验收的专用工厂电脑上保存 CA 私钥，限制操作员访问，保留离线备份。私钥永远不上传网站服务器或 GitHub，不分发给用户。服务器与固件中的都是 CA 公钥。

1. 工厂烧入 factory 镜像，核对准确板型和芯片版本。
2. 安装 `tools/requirements-factory.txt`，运行：
   `python tools/factory_station.py --port 串口 --device 12位MAC --issuer-key 工厂私钥.pem`
3. 核对工单并再次输入设备编号，生成设备身份；离线签发证书；固件用内置 CA 公钥验证证书后才写入；工具回读证书并验证随机挑战签名。无网络调用，无服务器登记。
4. 中断后用 `--resume` 恢复，保留已有私钥，不更换身份。工具生成的记录仅含公开身份及证书。
5. 刷入产品镜像、配套 SD 初始内容并执行验收。

普通用户拿到工厂镜像也没有 CA 私钥，无法给自己的板签发被服务器接受的证书。

## 黑名单

管理员页面 `/admin` 支持设备编号、原因、拉黑与解除拉黑。黑名单加密保存在网站服务持久化数据中，服务重启和代码发布不会丢失。解除拉黑不会授予无证书设备权限。

网站新请求和旧挑战在验签时检查黑名单；拉黑后取消该设备仍在处理的网页 AI 请求。ESP relay 新请求同样检查。已建立的实时语音每 5 秒重新检查；黑名单服务不可用时连接也会关闭，拒绝继续放行。网络检查可能额外耗时，不能宣称严格 5 秒完成。

## 安全边界与未验证项

本次没有对真实设备烧写 eFuse；实现不能当作已完成量产安全认证。产品目标 ESP32-P4 rev 3.x，当前产品配置最低 3.1。

普通读 Flash 不会读出受保护 eFuse 私钥。仍须核对准确芯片批次的恶意固件防护：rev 3.x SDK 存在 `ECDSA_SOFTWARE_SET_K` 寄存器定义，而旧版 `ECDSA_ENABLE_SOFT_K` 不在 rev 3.x eFuse 表中。必须由乐鑫确认安全模式并实测软件选择 nonce、跨曲线/跨用途操作不能提取秘密。不能把旧版芯片设置直接套用，也不能用应用层检查约束任意用户固件。完成该项前不量产烧录，不承诺抵御任意固件、故障注入、侧信道或开封攻击。

允许任意自编固件，就不能完全阻止用户把真设备作为远程签名器。协议证明签名能力，无法证明设备与浏览器物理相邻。限流、单设备并发与黑名单限制此类滥用；不通过开启 Secure Boot 来禁止用户自编固件。

量产真机验收至少覆盖：保护位与证书回读；重刷/OTA/整片擦除后身份一致；Flash 克隆到其它板被拒绝；黑名单；重放/篡改/过期/拔线；工厂断电；恶意固件攻击；USB、屏幕、触摸、音频并发回归。
