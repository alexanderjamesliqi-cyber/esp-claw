# Spark 设备身份与出厂流程

## 当前状态

这是工程实现，不是已完成的量产安全认证。服务端已部署；固件以 ESP32-P4 rev 3.x 为目标。没有在本次任务中对真实设备烧写 eFuse。首次量产前必须完成下述真机验收。

## 私钥是否可读

出厂镜像在设备内用硬件熵源生成每台独立 P-256 密钥；私钥只在出厂阶段短暂存在 RAM，写入 KEY0 后清零，接口从不导出私钥。KEY0 设置 ECDSA 专用用途、读保护、写保护和用途写保护。正式固件通过硬件 ECDSA 签名，并从硬件重建公钥，不依赖 Flash/NVS 保存身份。

因此普通读 Flash、拷贝固件、恢复出厂设置或整片擦除 Flash 不会导出/复制/清除 eFuse 私钥。不能将此等同于已经证明能抵御任意恶意固件、故障注入、侧信道或开封分析。

重要的待验收项：rev 3.x 的 SDK 寄存器定义存在 `ECDSA_SOFTWARE_SET_K`。旧版本芯片的 `ECDSA_ENABLE_SOFT_K` eFuse 在 rev 3.x 表中不存在，不能把旧芯片设置直接套用。必须根据准确芯片批次与乐鑫确认安全签名模式，并实测软件选择 nonce、跨曲线/跨用途操作不能提取秘密。仅在应用里检查寄存器无法约束用户自己的固件。未完成该项前，不承诺“任意固件下私钥绝对不可提取”，也不进行量产烧录。

- [ESP-IDF v5.5.4 ECDSA 文档](https://github.com/espressif/esp-idf/blob/v5.5.4/docs/en/api-reference/peripherals/ecdsa.rst)
- [P4 rev 3.x ECDSA 寄存器](https://github.com/espressif/esp-idf/blob/v5.5.4/components/soc/esp32p4/register/hw_ver3/soc/ecdsa_reg.h)

## 授权和边界

- 服务端仅接受管理员在工厂登记的公钥。普通固件和出厂镜像的源码都不包含管理员密码、云 API Key 或厂商通用私钥。
- 未登记的其它板，即使生成了自己的密钥，也不能使用云端服务。
- 浏览器每次 AI 请求都通过串口让真设备签署一个 30 秒、绑定请求摘要、单次使用的挑战。断开串口后禁用并取消浏览器请求。
- ESP 独立文字/实时语音通过同一公钥登记表鉴权；每次 HTTP 请求或 WebSocket 建连使用新挑战。
- 允许用户烧入任意程序，就无法完全阻止他把真设备当作远程签名器。协议证明当前持有合法签名能力，不能证明设备与浏览器物理相邻。限流、单设备并发和吊销用于限制这种滥用。
- 不启用 Secure Boot 来禁止用户自编固件，不关闭下载模式。任意改写的用户程序可能故意烧毁尚未保护的其它 eFuse，让设备失效；“允许自由重刷”不保证能恢复恶意破坏的芯片。

## 出厂一次性步骤

1. 使用经硬件验收的同型号测试板确认 KEY0 未被现有安全功能占用，且芯片版本 >= 3.0。生产配置的产品镜像当前最低版本是 3.1，以其构建要求为准。
2. 下载 GitHub Actions 的 factory 和 product 构建产物。工厂镜像与产品镜像分区不同，仅用于新机/专用测试板；先保存全 Flash 和 SD 备份。使用对应构建产物里的 `flasher_args.json`，不能猜测地址，也不能将出厂镜像当普通升级包。
3. 工厂电脑安装 `tools/requirements-factory.txt` 后，连接工厂镜像控制台并运行：
   `python tools/factory_station.py --port 串口 --device 12位MAC --label 设备名称`
4. 工具先登录管理员，核对物理工单 MAC，要求再次输入设备编号，才发送一次性烧写命令。生成、保护、验签、公钥登记及线上 relay 验签逐步完成。中断后使用 `--resume`，不会重新生成身份。失败板隔离核查，不能强行重写 KEY0。
5. 工厂刷入 product 镜像和配套 SD 初始内容，并执行完整验收。只有经过服务端登记的设备才有权限；拿到相同的出厂固件不等于获得权限。

工厂管理员凭据通过隐藏输入读取，不放在参数、固件、Git 仓库或公开升级包中。工具保存的记录仅含公钥、设备编号和算法。

## 日常升级

已安装本版本身份协议的设备：

`python tools/update_device.py --port 串口 --firmware edge_agent.bin --sha256 发布清单中的SHA256`

工具读取当前运行分区，核对现有分区表，只更新 ota_0 或 ota_1 应用；保存旧应用备份，升级后再次核对同一公钥。不会写分区表、OTA 元数据、NVS、storage 或 eFuse。旧固件没有身份协议时，工具会拒绝猜测地址；首次导入由工厂流程完成。

需要 SD 资源升级时，合并更新官方 `labplus/` 资源，保留 `programs/`、用户文件、Wi-Fi、开机选择、scheduler 和 router 配置。完整擦除 Flash 仍保留身份，但会丢失用户配置；不要把完整擦除作为默认升级方式。

## 量产验收记录要求

- 真机芯片版本/批次、KEY0 用途和全部保护位；全流程签名验签。
- 普通升级、切换 OTA 槽、恢复初始配置、整片 Flash 擦除后，设备编号、公钥相同。
- 将 Flash 内容复制到未登记板，服务端拒绝；禁用已登记公钥后，网页与 relay 均拒绝。
- 重放、篡改消息、过期、拔线、并发签名、断电中断工厂写入/登记。
- 自编恶意固件尝试读取 KEY0、操控 nonce、改变曲线/用途；需得到芯片厂商明确的安全行为依据。
- 真实 USB、屏幕、触摸、麦克风、音频播放和语音并发回归。
